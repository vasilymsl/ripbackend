✅ 1. СОЗДАНА СТРУКТУРА INIT СКРИПТОВ:

   init-db/
     ├── 01-schema.sql      (создание таблиц, image_url как TEXT)
     └── 02-seed-data.sql   (начальные данные с data URI картинками)

   PostgreSQL автоматически выполняет все .sql файлы из 
   /docker-entrypoint-initdb.d/ при первом запуске контейнера.

✅ 2. ОБНОВЛЕН docker-compose.yaml:

   Добавлен volume:
     - ./init-db:/docker-entrypoint-initdb.d

   Теперь при каждом ПЕРВОМ запуске контейнера:
     → Выполняется 01-schema.sql (создание структуры)
     → Выполняется 02-seed-data.sql (вставка данных)
     → Картинки загружаются АВТОМАТИЧЕСКИ!

✅ 3. ИСПОЛЬЗОВАНЫ DATA URI (ВСТРОЕННЫЕ SVG):

   Вместо внешних URL (которые не работают):
     ❌ https://via.placeholder.com/...
     ❌ http://localhost:9000/...

   Используются data URI (встроенные SVG):
     ✅ data:image/svg+xml;base64,...

   Преимущества:
     ✓ Работают БЕЗ интернета
     ✓ Не зависят от MinIO
     ✓ Не зависят от внешних сервисов
     ✓ Картинки ВСЕГДА загружаются

✅ 4. ИСПРАВЛЕН КОД (GetFileURL):

   Теперь проверяет, является ли URL полным:
     - Если начинается с http:// или https:// → возвращает как есть
     - Если начинается с data: → возвращает как есть
     - Иначе → формирует MinIO URL

ПЕРВЫЙ ЗАПУСК (после удаления volume):

  1. docker-compose up -d
  2. PostgreSQL создает новую базу данных
  3. PostgreSQL выполняет init-db/01-schema.sql
     → Создаются таблицы (image_url = TEXT)
  4. PostgreSQL выполняет init-db/02-seed-data.sql
     → Вставляются 6 кредитов с data URI картинками
  5. go run cmd/lab1/main.go
     → GetFileURL видит data:image/... в image_url
     → Возвращает как есть (не добавляет префикс)
  6. Браузер получает data URI
     → Декодирует base64
     → Отображает встроенный SVG
  7. ✅ КАРТИНКИ РАБОТАЮТ!

ПОСЛЕДУЮЩИЕ ЗАПУСКИ:

  1. docker-compose up -d
     → PostgreSQL использует существующий volume
     → Init скрипты НЕ выполняются (уже выполнялись)
     → Данные сохранены в postgres_data volume
  2. go run cmd/lab1/main.go
     → Картинки загружаются из БД
  3. ✅ КАРТИНКИ РАБОТАЮТ!

Чтобы убедиться, что всё работает:

1. Остановить контейнеры:
   docker-compose down

2. Удалить volume PostgreSQL (ВАЖНО!):
   docker volume rm lab4_postgres_data

3. Запустить заново:
   docker-compose up -d

4. Подождать 10 секунд (пока БД инициализируется)

5. Проверить логи:
   docker-compose logs postgres | grep -i "database system is ready"

6. Проверить данные в БД:
   docker exec lab4-postgres-1 psql -U myuser -d credits \
     -c "SELECT id, title, LEFT(image_url, 30) FROM credits;"

   Результат должен быть:
     id | title                  | preview
     ---+------------------------+-------------------------
      1 | Потребительский кредит | data:image/svg+xml;base64,
      2 | Кредит наличными       | data:image/svg+xml;base64,
      ...

7. Запустить приложение:
   go run cmd/lab1/main.go

8. Открыть браузер:
   http://localhost:8080

9. ✅ КАРТИНКИ ДОЛЖНЫ ОТОБРАЖАТЬСЯ!

Q: Почему картинки не загружаются?
A: Проверь:
   1. Volume postgres_data был пересоздан?
   2. Init скрипты выполнились? (docker-compose logs postgres)
   3. image_url содержит data:image/...? (SELECT)

Q: Как заменить картинки на свои?
A: Два способа:
   1. Через API (POST /api/credits/{id}/image) - загрузка в MinIO
   2. Через UPDATE в БД - использовать data URI или внешний URL

Q: Data URI - это не слишком долго?
A: Нет! SVG base64 занимает ~800 символов, загружается мгновенно.

Q: Можно использовать внешние URL?
A: Да! GetFileURL проверяет http:// и https:// и возвращает как есть.
