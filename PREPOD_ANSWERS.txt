1. "ГДЕ ЗАГОЛОВОК ВРУЧНУЮ В INSOMNIA?"
═══════════════════════════════════════

ПРАВИЛЬНЫЙ СПОСОБ:

1. Открыть Insomnia
2. Выбрать запрос (например, GET /api/applications)
3. Перейти на вкладку "Header"
4. Нажать "Add"
5. Ввести ВРУЧНУЮ:
   
   Name:  Authorization
   Value: Bearer eyJhbGc...{полный_JWT_токен}

6. Отправить запрос

ВАЖНО: 
  - Заголовок Authorization
  - Значение: "Bearer " + токен (с пробелом после Bearer)
  - Токен получить из POST /api/users/login

═══════════════════════════════════════
2. "JWT ГДЕ В REDIS? JWT ЗАЧЕМ СЕССИЯ?"
═══════════════════════════════════════

ПРАВИЛЬНЫЙ ОТВЕТ:

JWT токены - STATELESS (без серверного состояния).
Сессии НЕ НУЖНЫ для JWT.

Redis используется ТОЛЬКО для:
  ✓ Blacklist отозванных токенов (при logout)
  ✓ Автоматическое удаление по TTL

ДЕМОНСТРАЦИЯ (БЕЗ СКРИПТОВ):

1. Запустить redis-cli:
   $ redis-cli

2. Показать все ключи:
   127.0.0.1:6379> KEYS "lab4_service.*"
   (пусто - нет logout)

3. Выполнить logout через Swagger/Insomnia

4. Снова проверить Redis:
   127.0.0.1:6379> KEYS "lab4_service.jwt_blacklist.*"
   1) "lab4_service.jwt_blacklist.eyJhbGc..."

5. Показать значение:
   127.0.0.1:6379> GET "lab4_service.jwt_blacklist.{токен}"
   "1"

ВЫВОД:
  - JWT не хранится в Redis
  - Только blacklist (отозванные токены)
  - TTL = время жизни JWT (24 часа)
