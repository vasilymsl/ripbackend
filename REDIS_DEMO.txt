========================================
  ДЕМОНСТРАЦИЯ REDIS ДЛЯ ПРЕПОДАВАТЕЛЯ
========================================

JWT токены - stateless (без серверного состояния).
Redis используется ТОЛЬКО для blacklist отозванных токенов.

========================================
  ШАГИ ДЕМОНСТРАЦИИ
========================================

1. ЗАПУСТИТЬ ПРИЛОЖЕНИЕ:
   go run cmd/lab1/main.go

2. ЗАЛОГИНИТЬСЯ (через Swagger или Insomnia):
   POST http://localhost:8080/api/users/login
   Body: {"username": "user1", "password": "password123"}
   
   Ответ: получите JWT токен

3. ПОКАЗАТЬ REDIS (пустой, т.к. нет logout):
   redis-cli
   KEYS "lab4_service.*"
   (результат: пусто)

4. ВЫПОЛНИТЬ LOGOUT:
   POST http://localhost:8080/api/users/logout
   Header: Authorization: Bearer {ваш_токен}

5. ПОКАЗАТЬ BLACKLIST В REDIS:
   redis-cli
   KEYS "lab4_service.jwt_blacklist.*"
   
   Результат: видим отозванный токен

6. ПОКАЗАТЬ СОДЕРЖИМОЕ BLACKLIST:
   GET "lab4_service.jwt_blacklist.{токен}"
   
   Результат: "1" (токен в blacklist)

========================================
  КОНЦЕПЦИЯ
========================================

JWT = JSON Web Token (самодостаточный токен)
  ✓ Содержит user_id, username, is_moderator
  ✓ Подписан секретным ключом (HS256)
  ✓ Не требует проверки в базе при каждом запросе

Redis Blacklist = отзыв токенов
  ✓ При logout токен добавляется в blacklist
  ✓ Middleware проверяет токен в blacklist
  ✓ Токены истекают автоматически (TTL = время жизни JWT)

========================================
  ВОПРОС: "JWT ЗАЧЕМ СЕССИЯ?"
========================================

ОТВЕТ: Сессии не нужны! JWT - stateless.

Redis используется ТОЛЬКО для:
  1. Blacklist отозванных токенов (logout)
  2. TTL автоматически удаляет старые токены

Сессии (userID -> token) НЕ ИСПОЛЬЗУЮТСЯ.
